HackerSec: SAST-gated adversarial pipeline

Static analysis decides which functions an LLM is allowed to see. Semgrep and Bandit gate the function. Flagged functions get same-file callers, a Joern data-flow path, and a CWE note, then a three-seat board. A logistic regression fitted only on the dev split turns those signals into the final yes or no.

How one function is decided

  1. 1. Paired functionPre-fix code is labeled vulnerable. The same function after the security commit is labeled fixed. Repositories are split 20/80 so no project is in both dev and test.
  2. 2. Semgrep + BanditTen Semgrep packs, INFO mapped to low, Bandit with -l -i. Findings outside the function span are dropped. Collisions on the same line and CWE are merged, and a second tool is kept as a tag. No finding means the function is safe and the LLM is never called.
  3. 3. Enrichment, only if flaggedSame-file callers and callees, a Joern flow from the function’s parameters to the sink lines, and a CWE or OWASP note (exact id first, then vector search).
  4. 4. BoardAttacker and Defender write independent briefs in parallel. A string check verifies the Defender’s sanitizer quote. The Judge (temperature 0, one vote) sees that check and both briefs.
  5. 5. FusionEight numbers already recorded by the run go into a logistic regression fit on flagged dev functions. Threshold 0.597. No extra model call.

What “SAST board + fusion” is

It is the final verdict of the evaluated pipeline, not a second scanner and not another LLM. Functions with no static finding stay safe. Flagged functions are scored from the Judge probability, Attacker confidence, Defender safety, whether the sanitizer quote was in the code, finding count, max severity, any Joern path, and whether both tools agreed.

Eval path and the live worker differ.

The benchmark uses deliberate_function plus the dev-fitted model in hackersec/evaluation/realworld/fusion.py. The Celery worker behind the upload UI still debates each finding separately and uses the older synthetic fusion classifier.

What the weights imply for a next run

Use the static packet as the attack brief

Drop the Attacker model call. Let the Defender answer the Semgrep, Bandit, and Joern packet, then the Judge. That restores a direct rebuttal, removes a seat whose confidence is nearly constant, and cuts the three prompts to two.

Split Joern paths into unfiltered and guarded

A flow that passes through a quote, a realpath, or a dominating check should not be the same feature as a flow that does not. The current any-taint bit is why the weight is negative.

A zero-token sink check for paths and requests

On path traversal the gate sees 17.9% of the vulnerable functions. An AST check for parameters flowing into file, archive, and HTTP calls would send those functions to the board without prompting the other 78%.
